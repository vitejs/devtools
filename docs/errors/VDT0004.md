# VDT0004: Inspect Storage Fallback

## Message

> Vite inspect could not write the `{archive}` archive to disk and now keeps new records in memory.

## Cause

The Vite inspect collector writes transform payloads and plugin-call records to archives in the Vite cache directory. When a write fails, for example because the disk is full or the directory became unwritable, the collector keeps the failed batch and every later record in memory. Every transform stays available in the Vite UI, and memory use grows until the dev server restarts.

## Example

Filling up the disk that holds `node_modules/.vite/devtools/inspect` while the dev server is transforming modules triggers this warning.

## Fix

Check that the Vite cache directory is writable and has free disk space, then restart the Vite dev server to resume writing to disk.

## Source

- [`packages/vite/src/node/inspect/store/payload.ts`](https://github.com/vitejs/devtools/blob/main/packages/vite/src/node/inspect/store/payload.ts) — the payload archive emits this when a batched write fails and it switches to in-memory payloads.
- [`packages/vite/src/node/inspect/store/plugin-calls.ts`](https://github.com/vitejs/devtools/blob/main/packages/vite/src/node/inspect/store/plugin-calls.ts) — the plugin-call archive emits this when a segment write fails and it switches to in-memory segments.
